# Data Classification in Practice

<p class="module-lede">Classification is a decision about how information must be accessed, used, stored, and shared. The label matters because it changes what a learner may do next.</p>

## Module Overview

This module teaches learners to recognize the sensitivity of information before they access, enter, store, export, or share it. It is important because correct tool use depends on understanding the content itself, including details hidden in screenshots, attachments, and free text.

::: warning DWIHN confirmation required
The proposal names four tiers but does not define their exact boundaries or handling rules. Insert DWIHN's approved definitions and required actions before delivery.
:::

## Learning objectives

By the end of this module, learners can:

- Describe the purpose of information classification.
- Apply the confirmed DWIHN tiers to realistic examples.
- Recognize sensitive details hidden in screenshots, attachments, and free text.
- Choose an allowed action or escalate an uncertain case.

### 1. Public, internal, confidential, and restricted information

**Detailed Explanation:** Classification groups information according to its sensitivity and required protection. Public information is approved for external distribution. Internal information is intended for authorized workforce use. Confidential and restricted information require increasingly limited access and stronger handling under DWIHN's policy.

**Key Points:**

- The content determines the classification, not only its filename.
- Higher sensitivity requires stronger access, storage, sharing, and tool controls.
- The course must use DWIHN's approved definitions, not generic assumptions.

::: tip Real-life example
A service description already published on DWIHN's website may be public. A draft operational report may be internal or confidential. An identifiable call transcript may require the strongest applicable controls.
:::

**Technical Example:** A file record may contain fields such as classification, owner, authorized roles, storage location, and retention requirement. Systems can enforce controls from these fields only when the classification is accurate.

**How It Works:**

1. Inspect the complete content and context.
2. Identify personal, health, operational, contractual, or security details.
3. Apply the highest relevant DWIHN classification.
4. Follow the access, storage, sharing, and AI-use rule for that tier.
5. Reassess when content is combined or changed.

**Where It Is Used:** Documents, emails, dashboards, case information, call records, screenshots, attachments, exports, training materials, and AI outputs.

**Common Mistakes or Confusions:**

- Believing all internal information has the same sensitivity.
- Applying a lower label because a file is inconvenient to handle.
- Forgetting that generated summaries may preserve source sensitivity.

### 2. The wallet analogy and memory techniques

**Detailed Explanation:** The wallet analogy helps beginners remember that different information deserves different protection. A public brochure may be handed out freely. An employee badge belongs to one authorized person. A payment card requires additional safeguards. A highly sensitive record needs the strongest protection and controlled access.

**Key Points:**

- An analogy supports memory but does not replace policy.
- Learners should connect each tier to an allowed action.
- When the analogy and policy appear to differ, the approved policy controls.

::: tip Real-life example
Before attaching a document to an AI prompt, the learner asks whether they would place it on a public counter, inside an employee-only folder, or in a strongly protected record system. The analogy starts the decision, while DWIHN policy provides the final answer.
:::

**Technical Example:** A user interface can reinforce memory with classification labels and short handling prompts before upload or sharing. The software prompt helps the user pause, but the person must still classify correctly.

**How It Works:**

1. Recall the simple protection analogy.
2. Compare the information with confirmed examples.
3. Locate the exact DWIHN policy definition.
4. Select the handling action required by that definition.
5. Ask the designated owner when no example fits.

**Where It Is Used:** Quick decisions before uploading, attaching, presenting, exporting, recording, or sharing information.

**Common Mistakes or Confusions:**

- Treating the analogy as a legal definition.
- Memorizing labels without learning the required actions.
- Guessing when a real example does not match the memory aid.

### 3. Classification decision scenarios

**Detailed Explanation:** Decision scenarios help learners practice the complete sequence: inspect the information, assign the confirmed classification, check the handling rule, and decide whether to proceed, reduce the information, choose another tool, or ask for help.

**Key Points:**

- Screenshots, metadata, free text, and combined details can change the answer.
- A decision needs both a classification and a permitted action.
- Uncertainty should lead to escalation, not a convenient guess.

::: tip Real-life example
A screenshot has no name but shows a rare service, date, ZIP code, and case number. The learner considers the combined information before deciding whether the image may be shown in training.
:::

**Technical Example:** A classification decision tree may ask whether information is publicly approved, intended only for workforce use, individually identifying, or subject to stronger controls. The final branch links to a handling rule.

**How It Works:**

1. Read the entire scenario.
2. Mark every potentially sensitive element.
3. Consider whether separate details identify someone when combined.
4. Choose the tier using the confirmed definitions.
5. State the resulting tool, access, storage, and sharing decision.

**Where It Is Used:** Training exercises, pre-upload checks, document reviews, dashboard exports, presentation preparation, and manager coaching.

**Common Mistakes or Confusions:**

- Looking only for a member name.
- Ignoring information in hidden columns or speaker notes.
- Giving the correct label but choosing an unauthorized action.

### 4. Using the quick-reference desk card

**Detailed Explanation:** The desk card should summarize each DWIHN classification, common examples, permitted storage and sharing locations, AI restrictions, and the contact for uncertain cases. It supports quick decisions but does not replace the full policy.

**Key Points:**

- The card must match the current approved policy.
- Every tier should connect to examples and required actions.
- The help contact and version date should be easy to find.

::: tip Real-life example
An administrator receives an unfamiliar report and checks the desk card. The report does not match a listed example, so the administrator pauses and contacts the designated policy owner rather than guessing.
:::

**Technical Example:** A digital desk card can link each classification to the current policy page and display a version date. This reduces the risk of staff relying on an outdated printed copy.

**How It Works:**

1. Identify the likely tier.
2. Compare the information with the card examples.
3. Read the required handling actions.
4. Follow the linked full policy when more detail is needed.
5. Contact the listed owner for an unresolved case.

**Where It Is Used:** At desks, in Teams, within the LMS, during tool selection, and as a manager coaching aid.

**Common Mistakes or Confusions:**

- Keeping an outdated copy.
- Treating the short card as a complete policy.
- Selecting the nearest example when the content requires escalation.

## Story: the revealing screenshot

A screenshot does not show a member's name. It does show a service date, ZIP code, case number, rare program, and a free-text note. Any one detail may appear harmless, but the combination could identify a person or reveal sensitive information.

Removing a name does not automatically make a record de-identified. For training, use a record created from scratch with fictional details.

## Where sensitive information hides

- File names, folder names, and document titles.
- Screenshots, browser tabs, notifications, and visible account names.
- Dates, locations, uncommon services, and case identifiers.
- Comments, tracked changes, speaker notes, and hidden spreadsheet columns.
- Free-text descriptions that combine personal details.
- AI outputs that repeat or infer information from the input.

## Interactive demonstration

Display a fictional screenshot with ten visible elements. Ask learners to mark every element that must be considered before the image is uploaded, shared, or shown during a recorded session. Reveal the elements one at a time and connect each one to the policy decision it affects.

## Problem-solving scenario

Taylor receives a spreadsheet labeled "Internal," but one hidden column contains member identifiers. The filename and label do not match the actual content.

Discuss:

1. Which evidence should control the classification?
2. What should Taylor avoid doing next?
3. Who should be contacted to correct the label or handling?
4. How could the training version be made safe?

## Best practices

- Classify the content, not merely its filename or location.
- Inspect the whole item, including metadata and hidden content.
- Use the highest applicable classification when information is combined.
- Reduce information to what the authorized task actually requires.
- Pause when the definition or permitted action is unclear.

## Common mistakes

- Looking only for names.
- Assuming internal information is public because it seems routine.
- Believing a screenshot is safer than the system it shows.
- Reusing real records in a training example.
- Treating classification as a one-time label that never needs review.
